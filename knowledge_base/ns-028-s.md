> Fictional Northstar Systems policy for this public demonstration. Not instructions for a real employer.

## Symptoms
An engineer needs access to a project repository.

## Prerequisites
Use a managed Northstar demo device and the approved work account. Check for an active service incident before changing local settings. Public demo actions never affect real accounts.

## Resolution
1. Confirm the reported symptom: An engineer needs access to a project repository.
2. Establish scope: affected user count, managed asset, location and time of onset. Check the developer service snapshot.
3. Guide the employee through the approved steps: Request membership with the repository owner, team and required role. Use the managed single-sign-on account and enrolled MFA. Test read access after approval. Keep tokens in the approved secret manager and never paste them into chat.
4. Record which check changed the outcome. Do not mark resolved until the employee confirms the affected workflow works.
5. If unresolved: Repository administrators grant the minimum approved role and review access periodically.

## Validation
Repeat the original affected workflow once. Record whether it succeeds, the service involved and the time. If it still fails, keep the ticket open and document the exact remaining symptom.

## Escalation
Repository administrators grant the minimum approved role and review access periodically.
Use High priority for multi-user disruption or suspected compromise, Medium for one blocked employee, and Low for a routine request with a workaround.

## Evidence and privacy
Record the asset identifier, error code and redacted diagnostic summary. Never collect passwords, recovery keys, MFA codes, private documents or full message contents.

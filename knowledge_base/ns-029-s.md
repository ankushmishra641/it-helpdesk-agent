# Internal portal unavailable — service desk runbook

Review due: 2027-01-20

> Fictional Northstar Systems policy for this public demonstration. Not instructions for a real employer.

## Symptoms
The company portal returns an error or does not load.

## Prerequisites
Use a managed Northstar demo device and the approved work account. Check for an active service incident before changing local settings. Public demo actions never affect real accounts.

## Resolution
1. Confirm the reported symptom: The company portal returns an error or does not load.
2. Establish scope: affected user count, managed asset, location and time of onset. Check the intranet service snapshot.
3. Guide the employee through the approved steps: Check the service snapshot. Confirm whether other sites work. Try a private browser window and the approved network. Record the error code and approximate time. Do not bypass certificate errors or use unverified mirror sites.
4. Record which check changed the outcome. Do not mark resolved until the employee confirms the affected workflow works.
5. If unresolved: Application Operations needs the affected page path, error code and scope of impact. Avoid including query strings with private data.

## Validation
Repeat the original affected workflow once. Record whether it succeeds, the service involved and the time. If it still fails, keep the ticket open and document the exact remaining symptom.

## Escalation
Application Operations needs the affected page path, error code and scope of impact. Avoid including query strings with private data.
Use High priority for multi-user disruption or suspected compromise, Medium for one blocked employee, and Low for a routine request with a workaround.

## Evidence and privacy
Record the asset identifier, error code and redacted diagnostic summary. Never collect passwords, recovery keys, MFA codes, private documents or full message contents.

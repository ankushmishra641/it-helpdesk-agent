# VPN connection timeout — service desk runbook
Category: Network

Review due: 2027-01-20

> Fictional Northstar Systems policy for this public demonstration. Not instructions for a real employer.

## Symptoms
GlobalProtect remains on Connecting or reports a gateway timeout.

## Prerequisites
Use a managed Northstar demo device and the approved work account. Check for an active service incident before changing local settings. Public demo actions never affect real accounts.

## Resolution
1. Confirm the reported symptom: GlobalProtect remains on Connecting or reports a gateway timeout.
2. Establish scope: affected user count, managed asset, location and time of onset. Check the vpn service snapshot.
3. Guide the employee through the approved steps: Confirm internet access by opening the company portal. Close other VPN clients. Select the Northstar gateway in the approved client. Reconnect once and approve the MFA prompt you initiated. If the service snapshot shows an incident, follow the incident workaround instead of reinstalling.
4. Record which check changed the outcome. Do not mark resolved until the employee confirms the affected workflow works.
5. If unresolved: Escalate after one retry with the client version, gateway region, error code and local timestamp. Never collect an MFA code.

## Validation
Repeat the original affected workflow once. Record whether it succeeds, the service involved and the time. If it still fails, keep the ticket open and document the exact remaining symptom.

## Escalation
Escalate after one retry with the client version, gateway region, error code and local timestamp. Never collect an MFA code.
Use High priority for multi-user disruption or suspected compromise, Medium for one blocked employee, and Low for a routine request with a workaround.

## Evidence and privacy
Record the asset identifier, error code and redacted diagnostic summary. Never collect passwords, recovery keys, MFA codes, private documents or full message contents.
